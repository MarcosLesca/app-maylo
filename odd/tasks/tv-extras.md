# TV extras: queue, continue watching, ambient TV, reactions, background control, history

Six additions to the TV cast feature, agreed from the proposal list (numbers 1, 2, 3, 4, 6, 8). Branch `feat/tv-extras`, stacked on `hub/2-control` (not merged yet).
Technical details per spec are filled from exploration; user wording is quoted verbatim.

## Specs

- **S1 Shared queue** (proposal 1, accepted: "la 1)"). Proposal text: "Los dos agregan videos a una cola desde el navegador, con el botón "Agregar a la cola" al lado de "Enviar a la tele". Cuando termina uno, la tele pasa sola al siguiente." Shared between both members (Supabase, realtime), visible and editable (remove, reorder not required) from the remote.
- **S2 Continue watching + next episode** (proposal 2, accepted: "la 2) sin el opcional" — the intro skip is OUT). Proposal text: "Guardar la posición de cada video (URL de la página + título) y que al volver a enviarlo arranque desde donde quedó." and "Detectar el link "siguiente episodio" en la página (el `detector-script` ya inspecciona el DOM) y ofrecerlo al terminar."
- **S3 Ambient mode on the TV** (proposal 3, accepted: "3) esta re copado sii que sea reloj, y cuenta regresiba"). Only a clock and a countdown — no lists, bills nor photos. The countdown targets a fixed anniversary date that repeats every year (user choice: "Fecha de aniversario fija, todos los años": "Cargan una vez el día que empezaron (ej. 14/03) y cuenta hasta el próximo 14/03, se repite cada año."). Shown by the TV browser receiver page while nothing is playing.
- **S4 Reactions on the other phone** (proposal 4, accepted: "4) solo que aparezca flotando en su telefono sin tocar el Tv"). Emoji or short message sent from the remote; it floats on the OTHER member's phone, never on the TV. User choice: "App abierta + notificación si está cerrada": "Flotan si tiene la app abierta; si no, le llega una push con el emoji/mensaje."
- **S5 Background control** (proposal 6, accepted: "6) Sii"). Proposal text: "play/pausa/±10 s sin abrir la app, y que los botones de volumen del teléfono controlen la tele. Esto va de la mano con un **foreground service** para que el proxy siga andando con la pantalla apagada". Native change: needs a new APK build, not OTA.
- **S6 Shared browser history** (proposal 8, accepted: "8) si"). Proposal text: ""lo último que vimos" en la pantalla de inicio, junto a los favoritos."

### Technical decisions (parent, from exploration)

- **D1 Playback end.** `Playback` (`src/features/cast/browser/cast-target.ts`) gains `ended: boolean`. Receiver: page status `ended` (already reported) must surface as `ended:true`, not just `paused`. DLNA: `ended` when `transportState()` is `STOPPED`/`NO_MEDIA_PRESENT` after having played, or position ≥ duration − 2 s. Polling for auto-advance runs in a module-level session controller (`src/features/cast/session/`) that keeps polling while a cast is active even when the remote sheet is closed (it lives as long as the app process; S5 keeps the process alive).
- **D2 Queue (S1).** Table `cast_queue` (migration `0016`): id, created_by (auth.uid), video_url, referer (frame pageUrl), user_agent, cookie (nullable; user accepted storing it, L5), page_url (top page), title, created_at; members-only RLS; realtime publication. A queued video that fails to load (e.g. expired link) shows "No se pudo reproducir. Abrí la página para enviarlo de nuevo." with a button that opens `page_url` in the browser. The cast sheet shows "Agregar a la cola" next to each TV/"Enviar a la tele" action; the remote shows the queue ("En cola", title + who added it, remove button). Auto-advance: when the current cast ends, the phone that is casting claims the oldest item by deleting it (`delete … where id = X` returning the row; only the phone whose delete returns the row casts it), then casts it to the same target.
- **D3 Continue watching (S2).** Table `watch_progress` (migration `0016`): key = normalized top `page_url` + title, position_s, duration_s, updated_at; shared. Saved every 10 s while playing and on stop. When casting something with saved position > 30 s and < duration − 60 s, ask "¿Seguir desde 23:10?" with "Seguir" / "Desde el principio"; resume seeks after playback starts (existing seek commands; no receiver page change). Reaching ≥ 95 % or `ended` deletes the row.
- **D4 Next episode (S2).** The detector reports a new `maylo-next` message `{url, label}` from the top page for the first link whose text or `rel=next`/aria-label matches next-episode wording (es/en: "siguiente", "próximo episodio", "siguiente capítulo", "next episode", "next"). When the cast ends and the queue is empty, the remote/notification offers "Siguiente episodio" which opens that URL in the in-app browser (the user then sends it; no auto-cast).
- **D5 History (S6).** Table `browser_history` (migration `0016`): unique url, title, last_watched_at, watched_by. Upserted each time a video is cast (top page URL + page title). Start screen section "Lo último que vimos" (8 most recent) under Favoritos; tap opens it; each row can be removed.
- **D6 Ambient (S3).** Anniversary date stored in a shared settings table (migration `0017`, e.g. `couple_settings` single row with `anniversary_date date`), edited in the Aniversario tab ("Fecha de aniversario"). Inlined into the receiver page through `buildReceiverPage` (re-served when it changes). After 60 s idle with nothing playing, the TV page shows a large clock (HH:MM, es-AR, updates each second, no seconds shown) and the countdown "Faltan N días para nuestro aniversario" ("¡Mañana es nuestro aniversario!" at 1, "¡Hoy es nuestro aniversario! · N años juntos" on the day); any load/command returns to normal. Without a date only the clock shows. ES5, no external resources, dark tokens of `design/system.md`; slow position drift to avoid burn-in.
- **D7 Reactions (S4).** Table `reactions` (migration `0018`): id, created_by, emoji (≤ 16 chars) or message (≤ 80 chars), created_at; members-only RLS; realtime. Sending UI: a `ReactionBar` component (6 emojis + short text) mounted in the remote. Receiver: a global overlay in the root layout floats incoming reactions from the other member for ~4 s (Reanimated, respects reduced motion); push via the existing `notify_others` path with kind `reaction`, shown as a notification only when the app is not in foreground (foreground shows the overlay, not a banner); the headless background task handles kind `reaction`.
- **D8 Background control (S5).** Native in `modules/tv-cast`: a foreground service (type mediaPlayback) with a MediaSession + MediaStyle notification (title, sender, play/pause, −10 s, +10 s, stop) visible on lock screen; partial wake lock + Wi-Fi lock while active; remote volume via `VolumeProviderCompat` so the phone's volume buttons change the TV volume while casting. JS API in `modules/tv-cast/index.ts` (optional methods for old APKs) + a JS bridge in `src/features/cast/background/` mapping native actions to the cast control. Needs a new APK.
